## 2. The routes

### Route A — This repo, soul-line (THE LINE — works today)
A shared GitHub repo and page both sides read and write. This is the durable line: every request, pass, and answer lives here as a file, so nothing is lost when a call ends and either side can catch up by reading.

**Links:**
- Repo: https://github.com/uncommonpope-png/soul-line
- Page: https://uncommonpope-png.github.io/soul-line/

**Layout:**
- `messages/soul-to-betty/` — Soul's deliveries and questions to Betty.
- `messages/betty-to-soul/` — Betty's answers and reviews to Soul.
- `pictures/` — picture passes. `videos/` — video passes.
- `soul-picture-making-guide.md` — the full picture workflow for Soul.
- `soul-communication-line.md` — this file.

**Message format — one markdown file per message:**
- Filename: `YYYY-MM-DD-HHMM-short-subject.md` (e.g. `2026-11-06-1930-batch-53-passes.md`), in the direction's folder.
- Every file starts with this header:
```markdown
From: Soul
To: Betty
Date: 2026-11-06 19:30 CST
Subject: Batch 53 — 6 passes, 2 empty
Needs reply by: (date, or "none")
---
[Body: what happened, file paths, flags, what you need from Betty.]
```
- **Batch deliveries go here too:** after finishing a batch, Soul writes one delivery file in `messages/soul-to-betty/` with the batch number, pass/fail counts, the file paths of every pass, the flags on each pass, and the empty slots. Betty replies in `messages/betty-to-soul/` with her full-size review (approved / needs fix / rejected, with reasons).
- **Checking rhythm:** Betty checks the repo at the start of each work session and on her Profit-wire rounds; Soul checks `messages/betty-to-soul/` before starting each batch. Neither side should assume a message was seen until the other side answers in the repo or via Daniel.
- **Limit:** file-based, not live. Anything that needs an answer in minutes goes through Daniel (Route B).

## 4. Rules of the line

- **Betty reviews Soul's work first.** Soul sends passes to Betty (repo delivery file + file paths). Betty checks them at full size against the guide's verification checklist before anything is shown to Pope/Ms GCP. Nothing Soul makes goes out unreviewed.
- **Nothing posts without Ms GCP's approval of the exact post.** Same gate as always. Soul never publishes.
- **One message, one subject.** A delivery file is about one batch. A question file asks one thing. Long threads get lost.
- **Name the files plainly.** Batch, slot, product, and outcome in the filename or the first line — never "stuff" or "things".
- **Flags travel with the work.** A faint tattoo mark, a clipped sign, a second purse in frame — Soul writes the flag in the delivery file. Betty/Pope decide. Never hide a flag to make a batch look cleaner.
- **If a route goes quiet for more than a day, say so in the repo** — "No answer from Betty since [date]" — so the silence is visible instead of assumed.
